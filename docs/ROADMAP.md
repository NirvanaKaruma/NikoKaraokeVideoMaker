## 主线排期

### 0.4.0「可视化本体升级」

> 目标：把音频可视化从"单一频谱柱"升级为"可选形态 + 多频段驱动"。
> 技术前提：预览/导出共用同一套频谱输出（spectrumAt）与 SceneLayers 绘制——形态预设只改绘制分支，零架构变更。

- ☑ **形态预设库**（VisualizerConfig.style 扩展为枚举）
  - 形态：柱形（现有）/ 径向环形 / 示波器曲线 / 连续面积 / 点阵 / 流动光带（镜像柱·中心对称按用户反馈删除）
  - 预览与导出同一 enum + 同一绘制代码（核心约束 A）
- ☑ **平滑惯性**
  - attack/decay 双系数（上升快、下降慢，替换现有单系数平滑）
  - 经典"频谱帽"下落动画（每柱峰值保持 + 缓慢回落）
  - 纯 TS（shared/spectrum.ts 扩展），预览/导出共用
- ☑ **频段分离驱动**
  - 把频率范围按**人对数感知**分成几个频段（bass / low-mid / mid / treble），各算能量（0–1）
  - 频段能量 → 能量总线：bass→背景呼吸/踩点闪光（0.5.0 消费）
  - 供 0.5.0 的动效层消费；导出按帧时刻 t 计算同一能量值（所见即所得）

验收：每种形态在预览与导出中一致；切断音频时全部形态静止；频段能量在导出帧间连续变化。⚠ 已知残留：flow 波动强度/暂停相位等修复已过，0.4.0 范围内无未决项。

### 0.5.0「动效与后期」

> 目标：画面"活起来"——背景/主图/文本/全局各类可选特效。
> 技术前提：新增 **CanvasFX 管线**（纯函数 `(ctx, tSec, params) => void`，预览 overlay 与导出 compose 共用），
> 粒子类效果经 seeded RNG（mulberry32）按"全局时间种子"生成 30/60fps 一致序列。

- ☑ **背景特效**：Ken Burns 慢速缩放平移（无露边契约）、随 bass 呼吸的亮度/色相（消费 0.4.0 能量总线）
- ☑ **主图特效**：呼吸缩放、微旋转、发光脉冲、形状遮罩（圆/星形）、边框装饰
- ☑ **文本特效**：入场动画（淡入 / 滑入 / 打字机 / 弹跳；TextNode 加入场参数）
  - ⚠ 偏差：ROADMAP 原"逐字弹跳"受 Konva 单文本节点/自动换行限制，0.5.0 实现为**整体回弹入场**；逐字弹跳需重建文本排版（按字符拆分节点），列入后续考虑。
- ☑ **全局后期**（CanvasFX 管线）：
  - 暗角、胶片颗粒、扫描线、踩点闪光（bass 能量阶跃触发）、光斑/漏光（程序化素材 + globalCompositeOperation）
- ☑ **片头/片尾**：淡入黑场、标题卡（复用歌名/作者样式）、片尾淡出（时间函数）
- ⛔ **明确不做**：Bloom / 色差等重级后期（需 WebGL 渲染管线改造，收益/成本不划算）

验收：任意组合特效预览与导出一致（hasDynamicFx 双路径：默认关=静态缓存与 0.4.0 一致）；动效时间函数对 30/60fps 网格在共享 tSec 上输出相同（种子=时间）。

### 0.6.0「音乐响应进阶」

> 目标：让画面踩到音乐的"点"上。依赖 0.4.0 的能量总线与 0.5.0 CanvasFX 管线。
> ⚠ 2026-08-29 用户修订：**不做自动节拍检测**（onset/BPM 估计取消），节拍源改为**手动输入**（音乐 BPM 或单次周期秒），踩点由该节拍网格确定性驱动。

- ☑ **节拍源（手动）**：layout.visualizer 的 bpm / beatIntervalSec（**自由正数输入，不限范围**，BPM 优先；纯函数 beatPeriod/beatPhase/beatEnvelope——确定性、30/60fps 一致）
- ☑ **踩点触发**：脉冲（背景亮度短闪 + 主图 Kick 缩放）/ 闪光（CanvasFX beatFlash 手动节拍源优先，能量阶跃为第二来源）/ 粒子爆发（beat 起点喷发）
- ☑ **粒子系统成体系**：雪 / 樱花 / 星空 / 气泡 四预设 + 密度 + 爆发强度（每粒子固定种子独立循环轨迹；seeded RNG 保证 30/60fps 导出一致）

验收：手动 BPM/周期秒指定 → 踩点事件在预览与导出逐帧一致（同 t 同触发）；三种踩点效果（脉冲/闪光/粒子爆发）各自生效（smoke 各自像素校验）；粒子 30/60fps 序列一致。

### 0.7.0「音频工程」

> 目标：KTV 场景的"前奏/留白/同步"刚需。技术前提：现有 ffmpeg 混流管线只需加滤镜参数。

- ☑ **前导静音**（KTV 常需 2–3s 前奏留白）：merge 加 `afade=…,adelay=延迟:all=1,apad`（fade 作用于歌曲本体、delay 置后）；视频编码时长 +延迟；前奏画面 = 黑场/标题卡填充（introOutro 时间函数总轴平移），避免 `-shortest` 截断
  - ⚠ 决策：前导**仅作用导出侧**（预览编辑态保持原音轨——编辑/试听不等待），验收以导出为准
- ☑ **淡入淡出**：`afade=t=in:st=0:d=fadeIn` 与 `afade=t=out:st=dur-fadeOut:d=fadeOut`（0–10s 滑块，面板分组「音频工程」；选做"音量曲线"未做——afade 曲线已覆盖常规 KTV 诉求）
- ☑ **可视化-音频偏移校准**（ms 级，±500ms 滑块在预览播放区）：analyzer 取 `t + offset`（修复负偏移被 `>0` 守卫静默钳 0 的偏差），布局字段存储，预览/导出同偏移
- ☑ **健康项·超长音频护栏**（本版追加）：>40min 醒目警告提示；>60min 拒绝导入并明示原因（解码内存随时长线性 ≈60min 1.27GB）；导入前 ffmpeg 探测容器头时长（不解码）+ Worker 流式字节硬上限兜底

验收：前奏留白导出后音画同步（smoke-export af 用例：lead 2s + fade 0.5s → ffprobe 视频流时长=音频+2s、抽帧 0.5s 纯黑（H.264 有限范围 Y≈16）、标题卡可读、淡出段帧间差异、片尾近黑全绿）；偏移量 ±500ms 内可视校正所见即所得。

### 0.8.0「素材与排版」

> 目标：输入侧"够用"——Logo/字体/主题色。纯 TS / 现有 Konva 能力。

- ☑ **附加图像层**（logo / 水印 / 贴纸）：**多层自由增删**（数组化模型，z 序=数组序，上移/下移/删除）；拖动/等比缩放/透明度/四角快速摆位；**与主图同等级完整 fx**——主图动效（呼吸/微旋转/发光脉冲/遮罩/描边）提取为共享组件（SharedImageLayer/SharedImageFxLayer）全量复用 + 层入场动画（fade/slide/bounce，确定性时间函数）
- ☑ **自定义字体**：FontFace API 加载本地 ttf/otf（同进程预览/导出同字形）；家庭名 = NikoCustom-<文件基名>（确定性）
  - ⚠ 用户修订：**不内嵌**（初版方案为 base64 内嵌）——项目文件仅存路径引用（同音频模型）；换机器/缺文件 → 回退默认字体并提示
- ⛔ **自动主题色**（曾实现后**移除**——用户验收时认为没必要：提取主色的用途有限且改动属锦上添花）：已删除实现/UI/测试（git 历史与 DECISIONS §23 留档）

验收：附加层在 .niko 保存/还原（smoke-project：两层 Logo+Watermark 保存→还原→层数/图像/解码校验 ✓）；自定义字体导出与预览字形一致（同进程 FontFace；smoke-project 路径保存/还原 ✓）。

### 0.9.0「编辑器体验」

> 目标：多人协作与精细调整（撤销/重做 与 i18n 已在 0.3.0 完成，本版本聚焦其余项）。

- ☑ **图层面板**：z 序 / 锁定 / 隐藏（SceneLayers 按序渲染，导出同源）
  - 范围（用户确认）：**全部场景元素自由排序**（背景/主图/歌名/作者/可视化/每个附加层）；片头片尾黑幕与全局后期属特效叠加层永远置顶
  - 隐藏 = 不渲染（预览/导出同一渲染代码）；锁定 = **画布锁定**（不可选中/拖动/缩放，参数面板仍可调）
  - 自定义 z 序 → 导出走全层逐帧路径（hasCustomLayerOrder）——任意排序所见即所得
- ☑ **吸附对齐线**：拖动回调 + 阈值吸附（画布中心/边缘 + 元素间边/中线；阈值 8 逻辑像素；可开关）
- ☑ **数值精调面板**：DeferredSlider 补数字输入框（精确值/键盘微调，↑↓ 步进、Shift×10、回车/失焦提交；百分比×100 单位换算）

验收：图层隐藏/锁定在导出中被继承（smoke-visual 隐藏主图像素探针 + draggable=false 探针；smoke-project 锁定/隐藏/自定义序 保存→还原 ✓）；吸附在预览中有效且不误吸附（snap.test 5 项：中心/边缘/元素间/阈值外不吸 ✓）。

### 1.0.0「时间轴与多场景」（里程碑）

> 目标：任意的"随时间变化"——工程最大的一项，独立成里程碑。
> 技术前提：插值引擎产出"每帧 layout patch"，预览与导出应用同一 patch（核心约束 A 的自然延伸）。

- ✅ **关键帧/时间轴系统**（1.0.0 完成）：
  - 数据模型：属性路径 → 关键帧数组（时间/值/缓动曲线）——shared/timeline.ts（纯函数引擎，相对片段秒）
  - 插值引擎（纯函数）：`t → ProjectLayout`（resolveLayoutAt；数值 lerp / #rrggbb 通道插值；缓动注入 fx.ts）
  - 时间轴 UI：底部 TimelineBar（播放头/片段块/分割/删除/边界拖拽/重叠标红）；关键帧编辑器（v1 目录 24 条属性 + 点拖拽/缓动/捕获面板值）
  - 导出接入：逐帧 t → resolve → setLayout（与预览同函数=核心约束 A）；time-smoke 像素级实证
- ✅ **多场景分镜**（1.0.0 完成）：场景片段 = 完整布局快照（继承式全局基线，一改即拆）；硬切 v1；重叠非破坏校验；音频变化自动修正边界
- ☐ **预设/模板系统**：整套风格参数存 JSON；内置模板（含复刻参考图风格）——随功能沉淀后独立成版（本版不做，留待后续）

验收记录（1.0.0）：smoke-time 引擎断言 + 预览像素断言通过；smoke-export 三路 done（流式写盘→合并→ffprobe）；慢盘背压探针通过（队列峰值=在途 1 块）；内存验收与 4GB VM 见 TEST.md。

## 明确不做 / 远期探索

| 项 | 原因 |
|----|------|
| Bloom / 色差（重级后期） | 需 WebGL 渲染管线改造，导出路径重写收益/成本不划算 |
| 4K 导出移入 Worker + OffscreenCanvas | 瓶颈是编码器而非 UI（已用 MessageChannel 让出事件循环）；react-konva 无法直接跑 Worker，需重写渲染路径 |
| 批量导出队列 | 非 KTV 单曲场景刚需；后续用户按需再加 |
| 透明视频导出（VP9 alpha） | WebCodecs alpha 支持不确定；真需要时可走 ffmpeg `yuva420p` 路径，先原型验证再排期 |
